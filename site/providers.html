Providers

Orbit detects provider config in your tree and orchestrates the official CLIs. Detection is not the same as active ship scope.

Detection

ProviderDetectionTypical role
Cloudflarewrangler.tomlWorkers API, D1

Fly.iofly.tomlApps / containers
Netlifynetlify.tomlStatic sites

Cloudflare

Requires wrangler on PATH. Orbit uses login / whoami JSON, configure for D1 when applicable, deploy phases, and orbit secrets for documented Worker secrets. 

# Secrets (set via `wrangler secret put`):
# API_KEY_PEPPER, GITHUB_TOKEN

CORS_ORIGINS under [vars] feeds status recommendations. Localhost-only origins remind you before shipping a production frontend.

Vercel

Used for static docs and frontends. On full-stack with Cloudflare, Orbit can wire VITE_API_URL from the Worker URL before deploy.

Fly.io and Netlify

Detected when their config files exist. Choose them in orbit ship. Prefer each provider’s own docs for advanced flags; Orbit wraps the common path.

Scope vs detection

Detection answers what is in the repo. Scope answers what you are shipping now. A monorepo can detect Cloudflare and Vercel while status stays API-only until you pick Static site or Full-stack.

Common fixes

  • Doctor fails: install the scoped CLI, put it on PATH, then orbit login
  • Worker 1101 / 500: set required secrets with orbit secrets --put …
  • Health 404: use the path from status (often /v1/health)
  • Status still asks for Vercel: re-run orbit ship and choose API / backend only
  • Mid-deploy failure: orbit logs then orbit retry

Longer troubleshooting notes live in docs/troubleshooting.md.
